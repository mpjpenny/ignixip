Why is my VPN IP blacklisted?

Why a shared VPN exit ends up on blacklists, what you can do about it, and why a VPN does not clear a mail server's own listing.

A shared exit

A VPN sends your traffic out through an address that belongs to the operator, not to you. That address is an exit. It is not the address your ISP assigned, and it is rarely yours alone. Many people can use the same exit at once. Websites, mail servers, and blocklists see that shared address. They cannot see which customer made a given connection.

When one of those users sends spam, hosts a phishing page, or scans the internet, the lists record the exit. The next person handed that address inherits the listing. The sharing does not stop, so the listing comes back. The guide to a listed IP is what to do when you operate the address. This page is the case where you do not.

What the block actually is

A DNS blacklist, also called a DNSBL, publishes addresses through DNS. A mail server builds a query from the connecting address. If the list answers, the server can refuse the message, defer it, or file it. RFC 5782 describes that query. There is no single global list. A hit on one says nothing about the others.

Websites block exits for a different reason. Banks, shops, and login forms treat a shared datacentre address as a fraud risk, whether or not a DNSBL names it. A block page is not proof of a listing. A listing is not proof that your computer is infected. On a shared exit the reports usually belong to someone else.

Some lists cover a range rather than one address. UCEPROTECT Level 2 is one of those, and ignixip does check it, so another address in the same block can still be covered. Spamhaus is not in this check. Its rows say Not checked. A datacentre range is often on a Spamhaus policy list, which is not a spam verdict. Read the zone name at Spamhaus's own lookup before you treat it as abuse.

What you can do

Switch server

Another location is a different address. Check it before you rely on it. It is still shared, so it may already be listed, and someone else can list it again tomorrow. Switching helps when a site will not load. It does not remove the old address from any list.

An operator that retires bad exits

Some operators take abuse reports, disconnect the customers who caused them, and stop handing out an exit that stays listed. Judge the exit you were given: is it listed today, and is it still listed after you have sent nothing? Ask what they do with a listed exit. Do not pay a third party that promises to clear every list.

An address only you use

A dedicated address, sometimes sold as a static exit, is allocated to your account. Other customers no longer land on it, so a new listing is much more likely to be yours. You can stop the cause. Removal is still requested by the network that holds the address: a list wants that operator, not a person on a shared pool. The removal steps are what that operator follows.

Dedicated does not mean clean. The address can arrive listed from the previous tenant, and a range listing can still cover it. It remains a datacentre address, which some sites block with no DNSBL hit at all. If you send mail from it, it also needs matching reverse DNS. That check is the reverse DNS guide.

Why a VPN does not clear your mail server

A bounce names the IP that opened the SMTP connection. That is the mail server, or the provider's smarthost, not the laptop that submitted the message in a browser. A VPN on that laptop changes the address websites see when you read mail. It does not change the address in the bounce. The header guide shows how to pick the connecting address out of a Received line. Trust the address a server you trust wrote down.

Sending the server's own mail out through a VPN swaps its address for a shared exit. Receivers then see an address that is more likely to be listed, and that you cannot get removed, because you do not operate it. The server's own address stays listed for anyone who connects to it directly. Fix that address with the removal guide, or stop sending from it and use the provider's mail host. A home connection, and many datacentre ranges, are not supposed to send on port 25 at all.

Check the address you have now

Connect to the exit you want to test. Disconnect first if you want the address your ISP assigned.

  1. Open What is my IP and copy the address. That is the one this site sees. The full-report link on that page is a static page, and this site only publishes those for a fixed set of addresses, so paste yours into the check instead.
  2. Open the blacklist check. A link has the form /?tab=bl&ip=8.8.8.8. Replace 8.8.8.8 with the address you copied. For an IPv4 address it queries Barracuda BRBL, SpamCop, SORBS SPAM, SORBS HTTP, UCEPROTECT L1, UCEPROTECT L2, Abuse.ch SSLBL, and NordSpam, plus AbuseIPDB when that service answers. Spamhaus is marked Not checked. A clear result is not a Spamhaus clearance. Those eight lists are not queried for an IPv6 address. A website can still block an exit that no list names.
  3. The shorter blacklist check asks SpamCop, Barracuda, and UCEPROTECT Level 1 only. Use the link above for all eight. The IP lookup at /?tab=ip&ip=8.8.8.8&full=1 names the network and, when that source answers, whether the address is flagged as a VPN, a proxy, or Tor. Replace the example with your address. A hosting network is normal for an exit.
  4. If you will keep the address, watch it. This watch link is filled in for 8.8.8.8. Replace that address, leave Blacklist listings and delistings ticked, and submit. ignixip emails a confirmation. Alerts start after you open it, and only when a listing changes. The monitoring guide covers removing a watch. A watch does not follow you to a new exit. Add the new address when you switch.

Do not request removal for a shared exit. The list asks for the operator. A request from a customer on the pool is refused, and the next user would list the address again.

Questions

Will a VPN hide a mail server that is already listed?

No. Receivers see the IP that opens the SMTP connection. A VPN on the computer you read mail from does not change that address.

Does a clear result mean the exit is safe to send from?

No. Spamhaus is not queried, and sites block shared exits for reasons that are not a DNSBL. The same exit can be listed again the same day.
